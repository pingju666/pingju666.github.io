unordered_map介绍和基本操作

unordered_map是C++标准库中的一个高效关联容器，它提供了键值对的无序映射功能。与基于红黑树实现的有序容器map不同，unordered_map基于哈希表实现，虽然不保证元素的存储顺序，但能够提供平均常数时间复杂度(O(1))的查找、插入和删除操作，在大多数场景下性能更为出色。

基本特性

  • 键值对存储：存储(key-value)键值对，类似于字典结构
  • 键的唯一性：每个键在容器中是唯一的，不允许重复键
  • 无序存储：元素的存储顺序不确定，不按键的大小排序
  • 哈希表实现：底层采用哈希表数据结构
  • 高效操作：平均O(1)时间复杂度的查找、插入和删除操作

注意事项

  1. 下标访问: 使用[]运算符访问不存在的键时，会自动插入该键并默认初始化其值

  2. 迭代器: unordered_map的迭代器不支持随机访问，因此不能使用begin()+n这样的操作，需要使用advance()函数

  3. 哈希函数: 对于自定义类型作为键，需要提供相应的哈希函数和相等比较运算符

  4. 性能: 虽然平均时间复杂度是O(1)，但在最坏情况下（哈希冲突严重），性能可能退化为O(n)

  5. 顺序: 由于是无序容器，遍历顺序可能会随插入和删除操作而改变

常用成员函数

  • insert(): 插入键值对
  • erase(): 删除元素（通过键、迭代器或范围）
  • find(): 查找键，返回迭代器
  • count(): 统计键出现的次数（0或1）
  • empty(): 检查容器是否为空
  • size(): 获取容器中元素的数量
  • clear(): 清空容器
  • bucket_count(): 获取桶的数量
  • load_factor(): 获取负载因子

通过这些基本操作，我们可以灵活地使用unordered_map来处理需要快速查找的键值对存储场景。

3. 与map的性能比较

unordered_map和map各有优势，选择时应考虑具体需求：

特性 unordered_map map
实现方式 哈希表 红黑树
查找时间复杂度 平均O(1)，最坏O(n) O(log n)
插入时间复杂度 平均O(1)，最坏O(n) O(log n)
元素顺序 无序 按键排序
内存使用 通常更高 通常更紧凑
迭代器失效 插入时可能失效，删除时只影响当前元素 插入和删除不会使迭代器失效（指向被删除元素的迭代器除外）

4. 最佳实践

  1. 初始容量预留：如果大致知道元素数量，创建时指定合适的初始桶数量
  2. 避免频繁重哈希：大量插入操作前调用reserve()或rehash()
  3. 使用emplace而非operator[]：避免不必要的默认构造
  4. 注意哈希冲突：提供高质量的哈希函数，合理设置负载因子
  5. 选择合适的容器：对于频繁查找操作，unordered_map通常更好；对于需要排序或范围查询，map更合适
